Preflight

# 1. Database + app
make up
npm run dev                      # http://localhost:3000

# 2. PayPal webhooks reach your laptop (only for cards marked "money")
cloudflared tunnel --url http://localhost:3000
#   New URL each restart → update it in developer.paypal.com
#   (Apps & Credentials → app → Sandbox Webhooks → edit)

# 3. .env must have (values never committed):
#   PAYPAL_CLIENT_ID / PAYPAL_CLIENT_SECRET / PAYPAL_API_BASE (sandbox)
#   PAYPAL_WEBHOOK_ID       from the webhook you registered
#   SANDBOX_CLIENT_EMAIL    a sandbox PERSONAL account (pays invoices)
#   SANDBOX_CREATOR_EMAIL   a sandbox PERSONAL account (gets payouts), not the business one
#   CRON_SECRET             openssl rand -hex 32
#   PAYPAL_WEBHOOK_DEBUG=0  (1 only while debugging; logs contain emails)

# 4. Pick the data for the section you're testing
npm run db:seed:fresh            # start of demo: deposit not sent, nothing verified
npm run db:seed                  # mid-campaign: deposit paid, @jasonlifts payout awaiting approval

Every reseed creates a new campaign id: go back to / and open the campaign again; old tabs 404. Restart npm run dev after any .env or next.config.ts change. Cards tagged money make real sandbox PayPal calls (test money, but they draw down the sandbox balance). Keep a 4–7 MB image, a small PNG, a small PDF and an .svg handy for the upload cards.

W — PayPal webhook

W1 Unsigned requests are refused must pass
Do
curl -s -X POST localhost:3000/api/webhooks/paypal -d 'not json'
curl -s -X POST localhost:3000/api/webhooks/paypal \
  -d '{"id":"WH-FAKE","event_type":"INVOICING.INVOICE.PAID","resource":{"id":"INV2-X"}}'
Expect
  • Bad JSON → 400. Fake event → 401 Signature check failed. Nothing changes in the app.
A 200 for the fake event means anyone could mark invoices paid. Hard fail.
W2 A resent event is processed once money
Do
  1. developer.paypal.com → Event logs / Webhooks events → pick a delivered PAYMENT.PAYOUTS-ITEM.SUCCEEDED → Resend.
Expect
  • Dev log: POST /api/webhooks/paypal 200 with outcome duplicate. No second audit entry.
W3 Out-of-order and unknown events

Covered by webhooks.int.test.ts; no manual step

Expect
  • A late FAILED after SUCCEEDED keeps the payout paid. Events for unknown invoices/payouts are ignored. Batch events don't change anything.
