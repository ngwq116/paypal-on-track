2.5 Deploying to Vercel

About 45 minutes. The code is ready (vercel.json daily cron, GET on the daily-run route, a 1-connection database pool on Vercel). What's left is setup in Neon, Vercel and PayPal. Your local setup keeps working as before.

Before you start

  • The repo is pushed to GitHub (git push). Vercel deploys from GitHub.
  • Your local .env works: the app runs and the PayPal webhook works through the tunnel.
  • Have your .env open; most values are copied from it.

Step 1: Create the database (Neon, free)

  • neon.tech → sign in with GitHub → Create project (name on-track, region closest to you, e.g. Singapore).
  • On the project dashboard, Connection string → tick Pooled connection → copy it. It looks like postgresql://…-pooler….neon.tech/neondb?sslmode=require.
  • From the repo on your laptop, create the tables and the demo data in Neon (the URL on the command line wins over .env, so your local database is untouched): ``bash DATABASE_URL='<neon pooled url>' npx drizzle-kit push DATABASE_URL='<neon pooled url>' npm run db:seed ` db:seed loads the mid-demo campaign with your sandbox emails from .env. Use npm run db:seed:fresh or db:seed:roster` for the other starting points.

Step 2: Create the Vercel project

  • vercel.com → sign in with GitHub → Add New… → Project → import on-track.
  • Framework preset: Next.js (detected). Leave build and output settings as they are.
  • Before clicking Deploy, open Environment Variables and add these (Production):

| Name | Value | |---|---| | DATABASE_URL | the Neon pooled URL from step 1 | | PAYPAL_CLIENT_ID | from .env | | PAYPAL_CLIENT_SECRET | from .env | | PAYPAL_API_BASE | https://api-m.sandbox.paypal.com | | PAYPAL_WEBHOOK_ID | leave out for now (step 3) | | ANTHROPIC_API_KEY | from .env | | AI_MODEL | claude-haiku-5-5 | | CRON_SECRET | a new long random value: openssl rand -hex 32 | | SANDBOX_CLIENT_EMAIL, SANDBOX_CREATOR_EMAIL | from .env | | DEMO_RESET | 1 only if judges should be able to wipe and reload the demo; otherwise leave out |

  • Deploy. Note the URL, e.g. https://on-track-xxxx.vercel.app.

Step 3: Connect the PayPal webhook

  • developer.paypal.com → Apps & Credentials (Sandbox) → your app → Webhooks → Add Webhook.
  • URL: https://<your vercel url>/api/webhooks/paypal.
  • Events, the same as the tunnel webhook: Invoicing: Invoice paid and Payouts item: succeeded, failed, unclaimed, blocked, denied, returned.
  • Save, copy the new Webhook ID, and add it in Vercel → Project → Settings → Environment Variables as PAYPAL_WEBHOOK_ID.
  • Vercel → Deployments → latest → ⋯ → Redeploy. Environment variables only apply to new deployments.

Keep the old tunnel webhook too: each URL has its own webhook id, so local and Vercel both work.

Step 4: Limit the risk

  • The app has no login: anyone with the URL can approve and send sandbox payouts, trigger AI reads on your key, and download uploaded files. Share the URL only with judges.
  • Anthropic console → Settings → Limits: set a low monthly spend limit for the key used on Vercel (or create a separate key just for Vercel).
  • Optional: Vercel → Settings → Deployment Protection. It blocks strangers, but judges then need access, so check what your plan allows before turning it on.

Step 5: Check it works

  • curl -s -o /dev/null -w "%{http_code}\n" https://<your vercel url>/api/payouts/run-due → 401 (the daily run is locked without the secret).
  • Open the URL → top bar shows W Wanz; the seeded campaign opens on the Team view with both tables.
  • New campaign → drop eval/files/contract-kopi-kita.pdf → Read contract with AI → the review page fills in (10–20 s). Uploads must stay under 4 MB; Vercel rejects requests over 4.5 MB.
  • Deposit: on a campaign whose deposit isn't paid yet (the one you just created in 3, or seed Neon with db:seed:fresh), Send deposit → pay it as the sandbox client → within a few seconds the Team view shows Client deposit received. That proves the webhook reaches Vercel. If it doesn't, check PAYPAL_WEBHOOK_ID and that you redeployed; Check payment is the fallback.
  • Vercel → Project → Settings → Cron Jobs → Run next to /api/payouts/run-due → the function log shows 200 with {"today":…, "invoicesSettled":…, "results":[…], "payoutsSettled":…}. Careful: this sends any approved payouts that are due.

If something fails

  • Build fails on Vercel: run npm run build locally first; the same error shows there.
  • A 500 on every page: DATABASE_URL is missing or isn't the pooled URL; check the function logs (Deployments → latest → Logs).
  • "Signature check failed" (401) on the webhook: PAYPAL_WEBHOOK_ID is the tunnel webhook's id, not the Vercel one.
  • AI errors: same key rules as locally (workspace-scoped key); check the spend limit isn't reached.
  • The cron only runs once a day on the Hobby plan; use Send now in the approval queue for anything urgent.

# Database shell
docker compose exec db psql -U ontrack ontrack

# Campaign id

# Payouts with creator and status
docker compose exec -T db psql -U ontrack ontrack -c "select c.name, p.amount_cents, p.scheduled_for, p.status, p.status_reason, p.attempt, p.approved_by, p.paypal_batch_id from payouts p join assignments a on a.id = p.assignment_id join creators c on c.id = a.creator_id order by c.name"

# Last 15 audit entries
docker compose exec -T db psql -U ontrack ontrack -c "select at, actor, action, detail from audit_events order by at desc limit 15"

# Verifications (who/what checked each submission)
docker compose exec -T db psql -U ontrack ontrack -c "select c.name, v.source, v.task, v.pass, v.created_by, v.created_at from verifications v join submissions s on s.id = v.submission_id join assignments a on a.id = s.assignment_id join creators c on c.id = a.creator_id order by v.created_at"

# Client invoices
docker compose exec -T db psql -U ontrack ontrack -c "select kind, amount_cents, due_date, status, paypal_invoice_id from client_invoices"

# Webhook events received
docker compose exec -T db psql -U ontrack ontrack -c "select received_at, event_type, id from webhook_events order by received_at"

# Daily run with the secret
curl -s -X POST -H "Authorization: Bearer $(grep ^CRON_SECRET= .env | cut -d= -f2-)" http://localhost:3000/api/payouts/run-due
